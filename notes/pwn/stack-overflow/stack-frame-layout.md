## 概要

`push rbp; mov rbp, rsp` で始まる関数では、スタックフレームは次のように並ぶ（上ほど大きいアドレス）。

```
rbp+0x8   リターンアドレス（8 バイト）
rbp       saved rbp（呼び出し元の rbp、8 バイト）
rbp-0x8   カナリア（8 バイト。有効な場合）
  ...     アラインメント用の隙間（ある場合）
rbp-0xNN  ローカル変数（バッファの先頭）
```

バッファの先頭の位置は、`read` や `memset` などにバッファを渡している命令（`lea -0x70(%rbp), %rax` など）から読む。

## オフセットの計算例

`char buf[100]` が `rbp-0x70` にあり、カナリアが `rbp-0x8` にある場合。

```
offset   0〜99  : buf（100 バイト）
offset 100〜103 : アラインメント用の隙間（4 バイト）
offset 104〜111 : カナリア（0x70 - 0x8 = 104）
offset 112〜119 : saved rbp
offset 120〜127 : リターンアドレス
```

ペイロードは `パディング + カナリア + saved rbp の分の埋め + 飛び先のアドレス` の順になる。

## 注意点

- 宣言したサイズ（100 バイト）とカナリアまでの距離（104 バイト）は一致しないことがある。コンパイラがスタックを 16 バイト単位にそろえるため、隙間ができる。オフセットは必ず逆アセンブルから計算する。
- ループの `jmp` や条件分岐の飛び先は、命令の中に（相対オフセットとして）埋め込まれていて、コード領域は書き込めない。スタックを書き換えてもループの飛び先は変えられないので、制御を奪うのは関数が `ret` してリターンアドレスを使うとき。ループの中で書き換えたら、ループを抜けて関数から戻らせる。
- `rbp+0x8` がリターンアドレスになるのは、フレームポインタを使う関数で prologue を実行した後。`-fomit-frame-pointer` でビルドされた関数では rbp を基準にできない。
