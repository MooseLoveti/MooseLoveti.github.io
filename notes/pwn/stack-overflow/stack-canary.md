## 概要

スタックカナリア（Stack Canary）は、スタック上のローカル変数とリターンアドレスの間に置かれるランダムな値。関数の終わりで値が変わっていないかを確かめ、変わっていれば `__stack_chk_fail` でプロセスを落とす。バッファオーバーフローでリターンアドレスまで上書きすると、途中のカナリアも壊れるので検知される。

x86-64 の Linux（glibc）では、次のように作られる。

```
カーネル: プロセス起動時に 16 バイトの乱数を作る（補助ベクトルの AT_RANDOM）
   ↓
glibc:   その前半 8 バイトをコピーし、先頭 1 バイトを 00 に置き換えてカナリアにする
```

カナリアは `fs:0x28` に置かれ、関数の入口でスタックにコピーされる。

```
mov  %fs:0x28, %rax
mov  %rax, -0x8(%rbp)      ; カナリアは rbp-0x8
```

## 性質

- 先頭（最下位）の 1 バイトが必ず `00`。リトルエンディアンでメモリに並ぶと最初のバイトが `00` になるので、`puts` や `printf("%s")` などの文字列出力はそこで止まり、カナリアがそのまま漏れないようになっている。
- 検査は関数が `ret` する直前（エピローグ）に 1 回だけ行われる。関数の中のループで何度オーバーフローさせても、その関数から戻るまではチェックされない。

## 漏洩と書き戻しの手順

1. バッファの先頭からカナリアの先頭 1 バイト（`00`）までをちょうど埋める（バッファからカナリアまでの距離 + 1 バイト）。
2. 文字列出力でバッファを表示させる。`00` が消えているので、続く 7 バイトのカナリアまで出力される。
3. 漏れた 7 バイトの先頭に `00` を補ってカナリアを復元する。
4. もう一度オーバーフローさせ、カナリアの位置には復元した値を書き戻し、その先のリターンアドレスを書き換える。
5. 関数から戻らせる（ループを抜けさせる）と、検査を通過して書き換えたアドレスに飛ぶ。

カナリアの値は、補助ベクトルの `AT_RANDOM` が指す 16 バイトを読める状況なら、そこからも分かる（前半 8 バイトの先頭を `00` にしたもの）。

## 注意点

- 漏洩させる段階でカナリアの先頭を潰したままにしておくと、関数から戻った時点で落ちる。ループの中で漏洩させ、戻る前に正しい値を書き戻す。
- 書き込みの手段が「バッファの先頭から n バイトを同じ 1 文字で埋める」（`memset(buf, c, n)` など）しかない場合は、目的の値の末尾のバイトから順に書く。n を 1 ずつ減らしながら書くと、前に書いた後ろ側のバイトは残る（`EEEEE` → `DDDDE` → `CCCDE` → `BBCDE` → `ABCDE`）。カナリアの `00` も同じ方法で書き戻せる。
- カナリアは同じプロセスの中（fork した子プロセスも含む）では値が変わらない。
