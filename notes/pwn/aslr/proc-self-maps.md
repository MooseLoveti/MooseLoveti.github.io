## 概要

`/proc/<pid>/maps` には、そのプロセスのメモリ配置（実行ファイル、ライブラリ、ヒープ、スタックなどが、どのアドレスにどの権限でマップされているか）が書かれている。`/proc/self` は「読んだプロセス自身」を指すので、`/proc/self/maps` を読むと自分自身のメモリ配置が分かる。

ASLR は実行のたびにこれらのベースアドレスをランダムにするが、対象のプロセスに任意のファイルを読める脆弱性（パストラバーサルなど）があれば、そのプロセスに `/proc/self/maps` を読ませることでベースアドレスがそのまま漏れる。

```
$ cat /proc/self/maps
5583f0a00000-5583f0a02000 r--p 00000000 08:01 1234   /usr/bin/cat
7f2c1a400000-7f2c1a428000 r--p 00000000 08:01 5678   /usr/lib/x86_64-linux-gnu/libc.so.6
7ffd3c9e0000-7ffd3ca01000 rw-p 00000000 00:00 0      [stack]
...
```

## 注意点

- 端末で `cat /proc/self/maps` を実行して見えるのは `cat` 自身のメモリ配置で、攻撃したいプロセスのものではない。対象プロセスの中でファイルを読ませるか、`/proc/<pid>/maps` を指定する必要がある。
- 他のプロセスの `/proc/<pid>/maps` を読むには、そのプロセスを ptrace できる権限が必要。
- libc のベースが分かれば、libc 内の関数やガジェットのアドレスは「ベース + オフセット」で計算できる。
